**`github-sync sync`/`status` now recover from a deleted board or a lost sync map instead of leaving the mirror stuck.** Every mapped object (the Project board, its fields/options/labels/milestones, and every phase/plan issue) is classified `present`, `confirmed-absent`, or `unknown` on each run, derived from the reads the run already makes — never a dedicated probe. A bootstrap object confirmed absent twice, at least 60 seconds apart, causes `sync` to rebuild the whole bootstrap surface from `.planning/` (delegating to the same two-pass sequence `init` already runs) and continue into reconciliation in the same run — long, and always safe to interrupt, since every mutation stays checkpointed. `status` previews the identical rebuild scope without writing anything. **A deleted Project board can currently be rebuilt more than once from the same deletion** if a healthy recovery and a later run reading the still-stale configured project number interleave — extra, unused replacement boards can result; see the reference documentation for the current state of this gap. An issue's identity is re-resolved by `(owner, repo, number)` before it is ever declared absent, converging an issue moved off the board back to one object. For the more common case — a transferred issue whose project item stays bound to the board — a move within the configured repository self-heals the same way; **a move to a different repository is detected and reported instead of self-healing**, without ever repointing the mirror at a repository you did not configure. If `.planning/.github-sync.json` itself is lost, `sync` now re-binds a repository's own phase/plan issues from the identity markers already written into their bodies before creating anything, closing the recovery gap left open since Phase 4. Map pruning is not yet reachable in production for any orphaned phase, plan, or issue key — the absence marker its two-confirmed-absences gate requires is never persisted for those key forms, so this release currently removes no local map entries in practice — nothing on GitHub is ever deleted, closed, or unlinked. The 60-second recreate interval is a fixed constant, not a new configuration key; see the `github-sync` reference documentation for its provenance, its sample size, and what it does not rule out.
