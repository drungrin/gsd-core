**`github-sync sync`/`status` now recover from a deleted board or a lost sync map instead of duplicating work.** Every mapped object (the Project board, its fields/options/labels/milestones, and every phase/plan issue) is classified `present`, `confirmed-absent`, or `unknown` on each run, derived from the reads the run already makes — never a dedicated probe. A bootstrap object confirmed absent twice, at least 60 seconds apart, causes `sync` to rebuild the whole bootstrap surface from `.planning/` (delegating to the same two-pass sequence `init` already runs) and continue into reconciliation in the same run — long, and always safe to interrupt, since every mutation stays checkpointed. `status` previews the identical rebuild scope without writing anything. An issue's identity is re-resolved by `(owner, repo, number)` before it is ever declared absent, so a repository transfer self-heals instead of duplicating. If `.planning/.github-sync.json` itself is lost, `sync` now re-binds a repository's own phase/plan issues from the identity markers already written into their bodies before creating anything, closing the recovery gap left open since Phase 4. The only thing this release ever removes is a local map entry for an object the remote has confirmed gone twice — nothing on GitHub is ever deleted, closed, or unlinked. The 60-second recreate interval is a fixed constant, not a new configuration key; see the `github-sync` reference documentation for its provenance, its sample size, and what it does not rule out.
